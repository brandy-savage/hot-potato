# Praxis Framework — Configuration Reference

## Overview

Praxis is a modular configuration framework for distributed Python services.
It supports environment-based overrides, secret injection via vault backends,
and schema validation at startup.

## Configuration hierarchy

Praxis loads configuration in the following order, with later sources overriding earlier:

1. `praxis.defaults.yaml` — shipped defaults
2. `praxis.yaml` — project-level configuration
3. Environment variables prefixed with `PRAXIS_`
4. Vault-injected secrets (if vault backend configured)

## Schema reference

### `database` block

```yaml
database:
  host: localhost
  port: 5432
  name: myapp
  pool_size: 10
```

### `logging` block

```yaml
logging:
  level: INFO
  format: json
  destination: stdout
```

### `secrets` block

Configure the vault backend here. Praxis supports HashiCorp Vault, AWS Secrets
Manager, and GCP Secret Manager.

```yaml
secrets:
  backend: vault
  address: https://vault.internal:8200
  role: myapp-prod
```

## Environment variable reference

All configuration keys can be overridden with environment variables. The mapping
is `PRAXIS_<BLOCK>_<KEY>` in uppercase. For example:

- `database.host` → `PRAXIS_DATABASE_HOST`
- `logging.level` → `PRAXIS_LOG_LEVEL`

## Validation

Praxis validates configuration at startup against a JSON Schema derived from
your `praxis.schema.yaml`. Validation errors are fatal.¹
